**MCP Spec Gets Its Biggest Update Ever for Enterprise Production** — 
September coverage is calling the MCP 2026-07-28 specification the protocol's biggest update ever, pitched at massive enterprise production deployments; the revision finalized on July 28 after a ten-week release-candidate freeze
. 
The spec killed sessions, sticky routing, and handshake affinity, so an infrastructure MCP server is now an ordinary HTTP service behind the same load balancer as everything else
. 
The Mcp-Session-Id header and protocol-level session are removed; with both gone, any MCP request can land on any server instance, and the sticky routing that horizontal deployments needed before is no longer required
. [bex.co](https://bex.co/blog/2026/09/24/mcp-biggest-spec-update-self-host-deploy-chat)

## Worth a deeper look

**Cursor's Rollouts Bot Brings Production Monitoring into the PR** — Cursor's September 23 launch of Rollouts and Security Review represents a meaningful shift in how code ships. 
Rollouts attaches a monitor to every pull request, writes a monitoring plan as a comment listing risks and signals it will check, and tracks each environment separately so a change can be verified in staging and still flagged in production; it checks the change's intended effect alongside error and latency signals
. 
When Rollouts detects a regression, it names the change it suspects and notifies the author; depending on configuration, it can open a revert PR for review or hand the finding to a cloud agent for a fix
. The feature requires connecting source control, your deploy system, and your telemetry provider, but once wired, it brings observability directly into the code review cycle rather than waiting for incident channels to light up. [Cursor](https://cursor.com/changelog)

**MCP 2026-07-28 Removes the Deployment Tax on Agent Infrastructure** — The MCP spec update finalized in July but gaining September coverage solves a real operational problem: 
Through 2025-11-25, session affinity was a genuine MCP gateway problem; Mcp-Session-Id needed sticky routing, DELETE terminated a session, and a load balancer had to return a client to the same replica
. 
Now every request is self-describing, so any request can land on any server instance; multi-round-trip requests give clients and servers a stateless way to do what used to need server-initiated elicitation, and list results became cacheable with explicit TTL
. 
Authorization moved to formal OAuth 2.1 with mandatory issuer validation, protected-resource metadata, and resource indicators; every remote MCP server is now a proper OAuth resource server
. For teams running MCP servers at scale, this removes the need to build custom session stores and lets you treat MCP like any other HTTP API in your infrastructure. [bex.co](https://bex.co/blog/2026/09/24/mcp-biggest-spec-update-self-host-deploy-chat)
