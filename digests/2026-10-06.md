## ⚡ AI Productivity

**GitHub Copilot ships computer use for desktop apps** — 
GitHub launched computer use in public preview for GitHub Copilot CLI and the GitHub Copilot app on macOS and Windows, letting Copilot interact with desktop applications, navigate workflows, and help automate GUI-only tasks while keeping users in control. Computer use works best when you describe the outcome you want, the applications involved, and any important constraints.
 The feature requires explicit approval before controlling an app, with configurable allowed-app lists and organization settings that can disable it entirely. [GitHub Changelog](https://github.blog/changelog/2026-10-01-github-copilot-can-now-interact-with-desktop-apps)

**Replit Agent adds GPT-6.1 Sol and integrates Jev** — 
Replit added Jev in AI Integrations for building apps that classify content, route requests, and score leads with fast, structured AI decisions, and ships GPT-6.1 Sol and Claude Sonnet 5.5 when building with Agent. Sonnet 5.5 is available in Power mode, and GPT-6.1 Sol is available in Max mode.
 Users can ask Agent to "Use Jev via AI Integrations" to access structured-output classification without managing API keys. [Replit Release Notes](https://releasebot.io/updates/replit)

**GitHub Copilot code review gains API access** — 
GitHub added API support for Copilot code review through REST and GraphQL, with optional review effort settings for each request. Balanced is now the default review effort level.
 The changes are generally available to Copilot Pro, Pro+, Max, Business, and Enterprise plans as of October 2, allowing teams to trigger reviews from custom workflows. [GitHub Changelog](https://github.blog/changelog/2026-10-02-copilot-code-review-api-support-and-new-default-effort-level)

**Dynamic workflows land in GitHub Copilot** — 
Dynamic workflows let you define an orchestration in code that combines automated steps with agent work, running sequentially, in parallel, or both, with checkpoints for review and resume. Available on all Copilot plans in public preview.
 The feature ships across Copilot CLI (behind `--experimental` flag), the Copilot app (always on), and the Copilot SDK. [GitHub Releases](https://releases.sh/github)

**Gentlemen ransomware uses MCP as C2 channel** — 
A Russian-speaking Gentlemen ransomware affiliate used the Model Context Protocol (MCP) to execute commands during live intrusions, turning an AI coding assistant's tool interface into an operational command-and-control channel. CloudSEK identified the activity while investigating exposed infrastructure belonging to an operator calling himself Azazel, who invoked exec_in_session through an MCP service bound to 127.0.0.1:35367.
 The workflow demonstrates operational command execution rather than a theoretical exploit. [GBHackers](https://gbhackers.com/ransomware-affiliate-operations)

**OX Security discloses systemic MCP vulnerability** — 
OX Security researchers identified a systemic command injection vulnerability in Anthropic's MCP protocol that propagated across the AI ecosystem, with 200,000 vulnerable instances tied to a supply chain of 150 million-plus downloads. Anthropic called the behavior expected rather than patching it.
 Affected platforms include LangFlow, LiteLLM, Agent Zero, Windsurf, and nine other projects with critical CVEs. [OX Security](https://www.ox.security/blog/mcp-supply-chain-advisory-rce-vulnerabilities-across-the-ai-ecosystem/)

**Claude Code 2.1.286 fixes critical session bugs** — 
Claude Code 2.1.291 fixes regressions that could drop permission prompt answers and lose the last session messages on quit. A regression in 2.1.290 could drop answers to permission prompts in cloud sessions, and a regression in 2.1.288 could lose the last messages of a session when quitting.
 The updates shipped October 6, addressing reliability issues reported by production users. [Releasebot](https://releasebot.io/updates/anthropic/claude-code)

## Worth a deeper look

**The MCP security situation has escalated beyond theoretical** — Security researchers disclosed more than 40 CVEs against MCP implementations between January and April 2026, spanning Python, TypeScript, Java, and Rust SDKs. 
Researchers at Knostic scanned 1,862 internet-exposed MCP servers and found that not one of them had any authentication check in place. By early 2026, separate research had catalogued close to 7,000 internet-exposed MCP servers, with roughly half running with zero access controls. A team at Trend Micro manually verified a sample of these instances.
 The pattern points to a protocol that shipped fast and wide with security as an afterthought, and October 6's ransomware disclosure confirms the threat model is no longer hypothetical.
